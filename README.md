# Concord

Concord is a local-first collaborative document workspace. This repository is
being rebuilt around a self-engineered synchronization stack (CRDT core,
realtime gateway, durable update log); the current release is the verified
Phase 0 foundation: a modernized editor application with durable document
persistence and a vendor-neutral collaboration seam.

Additional engineering documentation: [docs/PRD.md](docs/PRD.md),
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md), [docs/DECISIONS.md](docs/DECISIONS.md),
[docs/ROADMAP.md](docs/ROADMAP.md).

## Current capabilities

- Email sign-in/sign-out and organizations via Clerk; all authorization
  decisions enforced server-side.
- Documents: create (blank or from templates), rename, delete, paginated
  listing, title search.
- Rich-text editor (TipTap): headings, styling, color/highlight, font
  family/size, line height, alignment, lists, tasks, tables, images with
  resize, links, local undo/redo, page margins with a draggable ruler, and
  export to JSON/HTML/TXT/print.
- Durable document content persistence (transitional whole-document saves with
  debounced writes, save-status indicator, and error surfacing).

## Intentionally deferred (not yet implemented)

Realtime multi-user collaboration, presence, comments/threads, and
notifications are intentionally unavailable while Concord's own
synchronization stack is built in later phases. The UI consumes a neutral
collaboration interface (`src/lib/collaboration/`) so these capabilities can
be added without re-coupling the product to a vendor.

## Requirements

- Node.js 24 (`.nvmrc` pins 24.20.0; `nvm use`)
- npm 11
- Docker (used by the Convex local development backend)

## Getting started

1. Install dependencies:

   ```bash
   npm ci
   ```

2. Configure environment variables in `.env.local`:

   - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
   - `CLERK_SECRET_KEY`
   - `CLERK_JWT_ISSUER_DOMAIN` (Clerk Frontend API URL)
   - A Clerk JWT template named `convex` must exist in the Clerk instance
     (audience `convex`, subject `{{user.id}}`, plus any custom claims such as
     `organization_id`).

3. Start the Convex local backend and apply the schema:

   ```bash
   npx convex dev
   ```

   The first run provisions a local deployment and writes `CONVEX_DEPLOYMENT`
   and `NEXT_PUBLIC_CONVEX_URL` to `.env.local`. Set the Clerk issuer on the
   deployment:

   ```bash
   npx convex env set CLERK_JWT_ISSUER_DOMAIN "<your Clerk Frontend API URL>"
   ```

4. Start the app (second terminal):

   ```bash
   npm run dev
   ```

5. Open [http://localhost:3000](http://localhost:3000).

## Verification

```bash
npm run typecheck   # TypeScript, strict
npm run lint        # ESLint (flat config)
npm test            # unit tests (vitest)
npm run build       # production build
npm run smoke       # HTTP smoke checks against a running server
```

## Environment variables

Variable names used by the app (values are secrets or machine-local and are
never committed):

- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
- `CLERK_SECRET_KEY`
- `CLERK_JWT_ISSUER_DOMAIN`
- `CONVEX_DEPLOYMENT`, `NEXT_PUBLIC_CONVEX_URL` (generated by `npx convex dev`)
